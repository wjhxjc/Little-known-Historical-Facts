## 一、背景与现状分析

项目是一个纯静态（HTML/CSS/JS）的"历史冷知识"科普小站，复古典籍风。核心数据文件 `js/facts.js` 以全局变量 `window.FACTS`（对象数组）形式存储所有冷知识，供 `home.js` / `fact.js` / `timeline.js` 三个渲染脚本读取。

**现状统计（已通过脚本核实）**：`js/facts.js` 当前实际有 **139 条**冷知识。

## 二、目标与非目标

### 目标
1. 向 `js/facts.js` 追加 20 条新冷知识（秦朝 13 条、元朝 7 条），使秦、元各达到 18 条，追平隋唐/明的水平。
2. 新增内容以"冷门/反常识"为首要选题标准，史料以正史为主、笔记/近人研究为辅并标注出处。
3. 同步 `js/facts.js` 头部注释与 `README.md` 中过时的事实性数字与朝代表述。
4. 严格遵循现有 schema 与写作体例，保证追加条目与既有 139 条风格一致。

### 非目标（YAGNI）
- 不做功能性改动（不改渲染逻辑、不改 CSS、不加新页面、不做 `待完成.txt` 里的语音/动画功能）。
- 不做全量数据体检（不核查现有 139 条的 id 重复/字段缺失等问题）。
- 不为"填满六个分类"而强行塞入平庸选题；分类均衡不作为选题取舍标准。
- 不改 README 的结构、部署教程、设计说明等非事实性内容。

## 六、数据 schema 与写作规范

每条新增冷知识严格遵循现有 schema（8 个字段，缺一不可）：

- `id`：kebab-case 英文，全局唯一，不与现有 139 条冲突
- `title`：标题，含反常识亮点
- `dynasty`：本批次只为"秦"或"元"
- `category`：六类白名单之一（帝王将相 / 风俗生活 / 文人轶事 / 战争军事 / 文化典籍 / 美食风物）
- `summary`：30–60 字一句话钩子
- `content`：正文 150–300 字，讲清"常识是什么 / 真相是什么 / 证据 / 为什么会误解"
- `tags`：3–5 个标签数组
- `source`：真实可查的史料出处

写作体例（对齐现有条目，如"蔡伦改良造纸术""汉代七十赐王杖"）：

- 正文 150–300 字，史料扎实、结论可考。
- 冷知识风格，开篇即给出反常识钩子。
- 笔墨扎实不浮夸，避免网络段子腔。
- 推测性内容（如秦始皇身高/疾病的现代医学解读、马可·波罗是否来华）必须用"后世推测""学界争议""可能"等限定语，不下定论。
- `source` 字段标注真实可查的出处。

## 八、验收标准

1. `js/facts.js` 中 `window.FACTS` 数组新增恰好 20 个对象（秦 13 + 元 7），总数从 139 增至 159。
2. 每个新对象的 8 个字段（id/title/dynasty/category/summary/content/tags/source）齐全，无字段缺失。
3. 每个新 id 全局唯一，与现有 139 条无冲突。
4. dynasty 字段值仅为"秦"或"元"；category 字段值在 6 类白名单内。
5. 每条正文长度在 150–300 字区间。
6. 每条 source 字段非空且指向真实可查史料。
7. 秦朝 13 条、元朝 7 条分别与本 spec 第四节、第五节选题清单一一对应（不漏条、不增条、不改钩子方向）。
8. `js/facts.js` 头部注释与 `README.md` 四处事实性表述按第七节方案更新完毕。
9. 新增条目插入位置：追加到 `window.FACTS` 数组末尾（结尾的 `];` 之前），不破坏既有条目顺序。
10. 浏览器打开 `index.html`、`timeline.html`、`fact.html`（取任一新 id）均能正常渲染，无 JS 报错。

## 九、风险与备注

- **秦第 1 条（秦始皇身高/疾病）**：现代医学解读部分属推测，实现时必须用"后世学者推测""疑似"等限定语，source 仍标注《史记》原文。
- **秦第 6 条（陈胜失期当斩）**：睡虎地秦简与《史记》存在出入是真实学术讨论，正文需呈现两方依据，不下绝对结论。这是高阶反常识，门槛略高但涨知识。
- **元第 2 条（四等人制）**：需明确区分"事实上存在民族等级差别"与"'四等人制'这个术语是近人概括"，不能因术语争议而否认历史不公。
- **元第 3 条（马可·波罗）**：必须保持中立，呈现否定派与肯定派（杨志玖等）双方的论据，不站队。
- **元第 5 条（收继婚）**：内容完全正经，聚焦蒙汉文化冲突，不涉低俗表述。
- **文档条数 159**：依赖实现时实际新增恰好 20 条；若实现中发现某条史料不可考需替换，条数仍维持 20，文档数字也仍为 159。
